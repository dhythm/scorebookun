# スマホ中心のリブランディング・機能再点検

2026年9月20日。基本的にスマートフォンだけで記録する前提。

## デザイン

- 深緑・生成り・白を基本とし、走者と現在回には琥珀色を使用。
- 試合中は「両チームの得点 → 回・アウト・走者・打者 → 試合操作 → 打順」の順。
- 得点とチーム名を常時表示し、イニング別スコアはスマホでは展開式。
- 戻す・走塁・結果入力は下部に固定。通知は入力ボタンを覆わない位置へ移動。
- 選手交代・メモ・試合終了はアイコンだけでなく名前を表示。
- 打順の自動縦スクロールを廃止。現在回への横スクロールは維持。
- 作成画面には登録人数と開始可能な状態を表示。履歴はチームと得点を2行で整理。
- 結果画面は最終得点と打撃成績を先に表示。投手成績は項目ごとに揃えて表示。

## 修正した機能上の問題

| 問題                                           | 修正・検証                                                                           |
| ---------------------------------------------- | ------------------------------------------------------------------------------------ |
| 任意イニングの `1.5` が1回として許可される     | 整数として厳密に検証。空欄・小数・範囲外を拒否                                       |
| 終盤の試合を開くと打順へ勝手にスクロールする   | 初回・打者更新・タブ切替でページ位置を維持                                           |
| 記録完了の通知が次の入力を覆う                 | 下部操作の上に配置し、登場時の移動も抑止                                             |
| 非DHで投手への代打後、救援投手が打順に入らない | 交代履歴から打順を継承した選手を特定。代走の連鎖・DH・旧記録も確認                   |
| 通常フライからの生還が犠飛にならない           | 有効得点と打点を確認して犠飛を導出。2アウト・得点取消・記録修正にも追従              |
| サヨナラ単打で余剰得点まで入る                 | 非本塁打は勝ち越しに必要な得点に制限。得点プレビュー・打点・個人得点・投手失点を統一 |

犠飛は保存済みの原記録を変更せず、表示・集計時に補正する。旧バグ経路で保存された
投手交代は内容を推測変更せず、従来どおり読み込む。新たな通常操作を修正する。
データベースの構造変更・本番データへの操作は行っていない。

犠飛の扱いは[MLB公式の定義](https://www.mlb.com/glossary/standard-stats/sacrifice-fly)を参照。

## 検証の範囲と残る確認

- 375×812pxで試合作成・満塁の試合中・結果入力シート・試合結果を目視確認。
- 長いチーム名と選手名、屋外モード、走者の44px以上の操作領域をE2Eで確認。
- 共有URL、別の記録者への反映、オフライン競合、履歴のエクスポート／インポートを確認。
- 物理端末の直射日光、画面ロックからの復帰、iPhone Safari/PWAでの1試合通し検証は未実施。
  [実機検証シート](device-validation.md)での確認が残る。
- リエントリー規則の警告や、大会ごとの細則の自動判定は対象外。
- 交代系記録の個別削除は未対応。直前の取り消しやイニング開始への復元を使用する。

### 残る機能上の課題

- 残塁は現在、3アウトで終わった回を対象に集計している
  （`lib/domain/stats.ts` の `getHalfInningLeftOnBase`）。
  サヨナラやコールドで途中終了した回の残塁がチーム合計に含まれないため、
  最終成績の精度を上げるには追加対応が必要。
- サヨナラ時の安打種別（二塁打を単打にする等）と超過進塁先は自動訂正しない。
  必要に応じて記録者が修正する。得点・打点は今回の修正で勝ち越しまでに統一。
